AI coding assistants write better Vue code when they read the real docs instead of guessing from memory. This page has rules for your repo and prompts that are specific to Vue. For the general setup (`llms.txt`, Markdown pages and what to give an assistant), see [Use net-watch with AI](/docs/ai/use-with-ai).

## Rules for AGENTS.md, CLAUDE.md or Cursor rules

Add this to your rules file, next to the general net-watch rules from the [AI page](/docs/ai/use-with-ai#rules-for-agentsmd-claudemd-or-cursor-rules). Replace `YOUR-SITE` with the address of this docs site.

```md title="AGENTS.md"
## net-watch with Vue

This app uses `@net-watch/vue` on top of `@net-watch/core`.

- Before writing net-watch code, read https://YOUR-SITE/docs/vue.md and https://YOUR-SITE/llms.txt. Do not rely on memory.
- Read the state with `useNetworkStatus(watcher)` from `@net-watch/vue`, passing the app's single watcher. It returns a computed ref: use `.value` in script, and keep the ref as a top-level binding so the template unwraps it.
- Create the banner in `onMounted` and destroy it in `onUnmounted`. It is plain DOM and must never run on the server.
- In Nuxt, create the watcher in a plain module such as `utils/network.ts`, render quality-dependent UI after mount or inside `<ClientOnly>`, and use a release after 0.1.0 (0.1.0 leaked one listener per server render).
- Never build online state with `navigator.onLine` or the `online` and `offline` events yourself.
- It needs Vue 3.3 or later.
- Only use options and fields that appear in the docs. Never invent an option.
```

## Ready-made prompts

Copy a prompt and paste it into your assistant. The address of this docs site is filled in on the deployed site (on a local copy it shows `YOUR-SITE`: replace it by hand).

<Prompt title="Add net-watch to my Vue app">
{`Add net-watch to this Vue project. Read https://YOUR-SITE/docs/vue.md and https://YOUR-SITE/docs/quick-start.md first, and follow the docs, not your memory. Do not invent options or fields.

1. Install @net-watch/core and @net-watch/vue with the package manager the project already uses. Vue must be version 3.3 or later.
2. Create ONE watcher in its own module with createNetworkWatcher({ pingUrl: '/api/ping' }), or use the project's existing health route as pingUrl. Import this watcher everywhere. In Nuxt, put it in utils/network.ts.
3. Create a Status component that calls useNetworkStatus(watcher). It returns a computed ref: read status.value in script, and use status.online in the template with the ref kept as a top-level binding. Show online or offline, plus the quality and the rtt in ms when they are known.
4. Wrap the app's fetch calls with watchFetch(watcher) from @net-watch/core/fetch and use the wrapped function in the API layer. Do not patch window.fetch.
5. Create the offline banner with createBanner from @net-watch/core/banner in onMounted, and call banner.destroy() in onUnmounted.
6. If this is Nuxt, render quality-dependent UI after mount or inside <ClientOnly>.
7. If there is no ping route, add one that answers HEAD and GET with 204 and Cache-Control: no-store.

Make the smallest change that works, run the type checker and the tests, and tell me which files you changed.`}
</Prompt>

## Tips

- **Say whether it is a plain Vue 3 app or Nuxt.** They differ in where the watcher module lives and how SSR is handled.
- **Say which version you use.** Run `npm ls @net-watch/vue` and include the version in your prompt.
- **Ask it to run the type checker.** A wrong option name fails `tsc` right away, which catches the most common mistake.
- **Review the ping endpoint yourself.** Check that it is not cached and runs before auth, or the app would look online forever.
